# DaimonCraft roadmap

The first playable slice drives the reusable core. Historical breadth remains
in [the recovered roadmap](history/ROADMAP.md), without pretending old completion
marks are acceptance of this fresh stack. GitHub Issues own current execution.

| Slice | Concrete result | Bootstrap status |
|---|---|---|
| 0. New Rust foundation | Separate core/body/CLI, bounded attention, correlated actions, uncertainty retained, runnable offline journey | Implemented as an offline fixture; local checks recorded in the founding issue |
| First live task: server only | Automatable Purpur development server with useful server resources enabled; inspect historical Legion/Inference01 baseline | [Issue 2](https://github.com/compaii/DaimonCraft/issues/2) owns actual deployment/evidence; [operator guide](SERVER.md) and [source reconciliation](history/SERVER-BASELINE.md) |
| 1. Live body | Pinned Rust Minecraft client, selected game version/world/login, observe/move/chat, stop and reconnect | Not implemented; Azalea is a candidate |
| 2. Live cognition | Provider adapter, selected supported access, model tools, deadline/cancellation, bounded usage, persistent conversational context | Not implemented; Instant is a candidate, not a selected paid route |
| 3. Matrix body and continuity | Supported same-being body admission, actual resource/lifecycle evidence, authorized DMK retrieval and episodic write route | Not implemented |
| 4. First shared playground | Nicolás joins, sees and converses with CompAII; move/interact/verify, interrupt and reconnect without duplicate action | Requires live slices and human acceptance |
| 5. Rich experience | Body interoception/reflexes, spatial memory, attention relevance, skills, reflection and voice | Incremental experiments after the playable slice |
| 6. General minimal harness | A second non-Minecraft body demonstrates reuse; versioned portable package for potential inheritance | Hypothesis to test; no species release/adoption |

APN is a requested influence whose exact source/name is not yet resolved. Keep
that question open without inventing an acronym expansion or holding the
independent Rust foundation idle.

The new project intentionally supersedes the earlier proposal to modernize
DaemonCraft in place. Do not start old services to satisfy this roadmap.
